# 项目关系与重构边界

| 项目         | 与新 CCbuddy 的关系            | 已采用的能力                                                      |
| ------------ | ------------------------------ | ----------------------------------------------------------------- |
| 上游底座项目 | 应用代码底座                   | pnpm monorepo、Electron/Web/CLI、共享 UI、架构门禁和 Agent 工作台 |
| 旧版 CCbuddy | 两项产品行为的参考实现         | 六来源只读会话查看、主子代理关联、跨会话日历时间线                |
| Codex        | 会话生产者与协议、安全设计参考 | Codex rollout 适配、版本化只读协议、解析器隔离、显式拒绝优先      |
| Grok Build   | 会话生产者与事件、存储设计参考 | Grok history 适配、可重建投影、刷新终态与失败可见性、两遍压缩     |

```text
Claude Code ──┐
Codex CLI ────┤
Qoder CLI ────┤  本地生产者记录 ──> 独立来源适配器 ──> 只读会话列表/正文
Grok Build ───┤                                      └──> 跨项目时间线
Copilot CLI ──┤
Antigravity ──┘

新 CCbuddy Agent ──> 基于上游底座项目的工作台、模型与工具执行链路
```

新 CCbuddy 保留上游底座项目的 Agent 工作台，并增加复盘其他 CLI 已写入记录的独立历史窗口。历史服务按生产者格式分适配器；目录索引只保留会话元数据，打开详情时重新读取对应记录。读取失败在界面可见，不能伪装成空历史。Grok Build 的权威流是 `updates.jsonl`；适配器优先读取已验证的 `chat_history.jsonl`，缺失时直接读取 `updates.jsonl`，不会写回生产者文件。本应用的索引和投影均可丢弃重建。

“只保留两项能力”仅限定从旧版 CCbuddy 迁入的功能：会话查看和时间线。旧版独立网关、插件、Skills、CLI 配置写入、用量监控面板、跨会话全文搜索、会话编辑、导入导出和续接均不迁入。旧版 Swift/GPL-3.0 源文件不进入新应用；迁移的是可观察行为。上游底座项目适用的许可与归属声明继续保留。

新 CCbuddy 只向用户自行配置的模型服务发送模型请求，不使用上游账号、订阅网关、内置凭据或默认模型。应用自有状态以 `~/.ccbuddy` 为唯一默认存储根目录；外部 CLI 会话文件仅是只读输入。安装包、命令、协议和界面均使用 CCbuddy 名称，原标识不作为兼容别名继续发布。

Agent 执行器已实现 Codex 式显式拒绝优先，以及受 Grok Build 启发的两遍会话压缩；压缩预摘要只是内存候选，最终摘要仍由正常压缩边界写入。Guardian 自动审核和操作系统强制沙箱尚未实现，不能把只读历史边界或命令规则称为执行沙箱。验收依据见[历史查看规范](specs/history-review.md)、[两遍压缩规范](specs/speculative-compaction.md)、[执行安全规范](specs/agent-execution-security.md)和[产品标识规范](specs/product-branding.md)。
